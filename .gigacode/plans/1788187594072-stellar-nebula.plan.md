# Implementation Plan: JWT Access/Refresh Token Management

## Summary
Add complete JWT token lifecycle management to the FastAPI mock server for training OAuth 2.0 flows without httpbin.org dependency.

## Approach
- Use `python-jose[cryptography]` for JWT signing (HS256)
- In-memory token storage (tokens are ephemeral)
- FastAPI `Depends()` for route protection
- Token rotation on refresh (OAuth 2.0 best practice)
- Follow existing conventions: Russian comments, emoji prefixes, Pydantic models

### Step 2: Create TokenStore Class
**File**: `data_store.py` (append after `RequestHistoryStore`)

```python
class TokenStore:
    """Хранилище токенов в памяти с поддержкой ротации и отзыва"""
    - access_tokens: Dict[str, Dict] - storage for access tokens
    - refresh_tokens: Dict[str, Dict] - storage for refresh tokens
    - Methods: store_access_token, store_refresh_token, validate_access_token,
      validate_refresh_token, revoke_token, rotate_refresh_token, get_token_info, count
```

Each token stores: token_id, user_id, token_type, created_at, expires_at, revoked flag

### Step 7: Create FastAPI Dependency
**File**: `mock_server.py` (after middleware section)

```python
async def get_current_user(
    authorization: Optional[str] = Header(None)
) -> Dict[str, Any]:
    """Validates Bearer access token via JWT decode + TokenStore check"""
    - Extract token from "Bearer <token>"
    - Decode JWT and validate signature/expiry
    - Check TokenStore for revocation
    - Return {user_id, role, token_jti} or raise 401
```

### Step 8: Add Authentication Endpoints

#### 8a. `POST /auth/login` (response_model=TokenResponse)
- Validate username/password against TEST_USERS
- Generate access_token (5min) + refresh_token (60min)
- Store metadata in TokenStore
- Return TokenResponse

#### 8b. `POST /auth/refresh` (response_model=TokenResponse)
- Decode and validate refresh_token
- Check TokenStore for revocation
- Generate new token pair
- Rotate: revoke old refresh token, store new pair
- Return new TokenResponse

#### 8c. `POST /auth/logout`
- Accept token in request body
- Revoke token in TokenStore
- Return success message

#### 8d. `GET /auth/validate?token=...` (response_model=TokenValidationResponse)
- Look up token in TokenStore
- Check JWT structure if not found in store
- Return detailed validation status

#### 8e. `GET /protected/data` (Depends(get_current_user))
- Requires valid Bearer access_token
- Returns mock sensitive data with user info
- Demonstrates protected resource flow

## Testing Strategy

### Test Classes to Add (`test/test_api.py`)

#### TestAuthPositive
1. **TC-A001**: Login with valid credentials → 200, returns tokens
2. **TC-A002**: Different users get different tokens
3. **TC-A003**: Access protected resource with valid token → 200
4. **TC-A004**: Refresh token → 200, new tokens issued (rotation)
5. **TC-A005**: Validate valid token → valid=True
6. **TC-A006**: Logout revokes token → subsequent requests get 401
7. **TC-A007**: Full lifecycle (login → use → refresh → use → logout)

#### TestAuthNegative
1. **TC-A010**: Login with wrong password → 401
2. **TC-A008**: Access protected resource without token → 401
3. **TC-A009**: Access with invalid token → 401
4. **TC-A011**: Refresh with expired token → 401
5. **TC-A012**: Refresh with already-used refresh token → 401 (rotation enforcement)
6. **TC-A013**: Validate revoked token → valid=False

## Verification

2. **Start server**: `python mock_server.py`
3. **Test login**: `curl -X POST http://127.0.0.1:8000/auth/login -H "Content-Type: application/json" -d '{"username":"admin","password":"admin123"}'`
4. **Test protected resource**: Use returned access_token with `Bearer` header
5. **Test refresh**: Use refresh_token to get new pair
6. **Test logout**: Revoke token and verify it's rejected
7. **Run tests**: `pytest test/ -v`

## Training Scenarios Enabled

1. **Token acquisition**: Login → receive access + refresh tokens
2. **Token usage**: Make authenticated requests with Bearer token
3. **Token expiration**: Wait for access token to expire, observe 401
4. **Token refresh**: Use refresh token to get new pair (rotation)
5. **Token revocation**: Logout to immediately invalidate token
6. **Refresh token expiration**: Wait for refresh token to expire, observe forced re-login
7. **Token validation**: Debug token status during training
